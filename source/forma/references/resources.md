# Executable resources and contracts

Consult this guide when reusing an asset or running a checker. Paths are relative to the installed skill's root, not a previous project's directory.

## Availability

**Executable lookup:** the [reference library](reference-library.md) includes a catalog with provenance, `scripts/references.mjs` for local selection and a [lookup page](../assets/reference-browser.html). `scripts/media.mjs` searches open collections and downloads only an explicitly selected result, with a receipt/credits and network/file limits. Local lookup requires Node 18+; media requires Node 22+ and network access. Implementation records and investigation guides are authored by Forma; the indexes of 202 websites and 2,079 portfolios preserve external names/URLs and provenance. Select the portfolio collection with `--portfolios`; malformed URLs are quarantined, and coverage has its own receipt. `--observed` selects a separate [dated claim index](../assets/reference-library/observed-experiences.json), currently six sources and ten observed claims. Its feature/use-case matches return supporting evidence and limitations; unsupported queries do not fall back to candidates. This subset does not establish that all indexed sites were studied. Guide associations are not current verification of the sites. Retrieved media retains external authorship and licensing. The guide describes commands, options, collection through the host browser and limits.

**Available portable code:** `BookObject`, `AppearanceEditor`, `NeuronPassport`, the legacy `PassportObject`, the `assets/library-colors.js` color helper and the [clean interface foundation](clean-shell.md). The [component integration guide](reusable-components.md) documents scoped styles, adapters, dependencies and lifecycle; the [component lab](../assets/components-lab.html) is a runnable consumer. AppearanceEditor includes direct lighting controls and explicit preview/Save/Cancel; its compact-profile fidelity still requires destination measurements. NeuronPassport extracts the approved CSS mechanism with its original lighting, shadow and motion layers. The legacy Three PassportObject is a separate simplified alternative. Routes, data, persistence, context and framework lifecycle remain the destination's responsibility. Reuse existing components and implement only what is missing.

**Documented knowledge:** the [approved CSS passport case](passport-polish-case-study.md), with a revision manifest and geometry/material/performance lessons. Its original application code remains in that consumer; the new Three component is a separate adaptation. The material-profile and fidelity contracts still need project-specific integration and evidence. The [release-validation protocol](release-validation.md) provides bounded trials, browser/input/runtime checks and retrieval review, not an executable test runner or a release approval.

Run commands using the absolute path of the folder where this skill is installed. The `check_*` scripts require only Python 3.9+, do not use the network and do not modify the project. Component regressions use Node; actual geometry uses the Three module supplied by the consumer:

- `python3 <skill-dir>/scripts/check_evidence.py <report.json>` checks the integrity and coverage of an evidence record. Format and limits are in [verification](verification.md).
- `python3 <skill-dir>/scripts/check_fidelity.py <contract.json> <observation.json>` compares every required measurement against independent expected values; missing data and mismatches fail. [Format, collection and limits](fidelity-contracts.md); [frozen compact-editor sample](../assets/reference-profiles/compact-appearance-v1.fidelity.json). It does not collect browser data, compare pixels or certify the product.
- `python3 <skill-dir>/scripts/check_contrast.py '#111827' '#ffffff' --threshold 4.5` calculates WCAG contrast for two opaque sRGB colors. It does not validate gradients, transparency or interface conformance.
- `python3 <skill-dir>/scripts/check_layout.py <layout.json>` verifies declared geometry contracts against measured boxes: alignment, center, inset, gap, containment and overflow. It does not assess perceptual quality by itself; format and limits are in [spatial contracts](layout-spatial-contracts.md).
- `python3 <skill-dir>/scripts/check_package.py --root <skill-dir>` checks structure, local links and inventory; for plugins it also checks the manifest, namespace and provenance. Optional installation and ZIP comparison is described in [plugin operation](plugin-operation.md). It does not run an agent, test UI or install resources.
- [Example tokens](../assets/tokens.example.json) and [example evidence](../assets/evidence.example.json) are starting points, not evidence from a real project. Never copy an approved status without executing the test.
- The [clean interface foundation](../assets/clean-shell.html) demonstrates a sidebar, surfaces, buttons, text search, fields and themes; [scoped CSS](../assets/clean-shell.css) and [demo JS](../assets/clean-shell.js) have no external dependencies. Item creation is in memory; it is not a backend, semantic search or automatic consumer integration.
- [BookObject](../assets/book-object.js) is an original implementation of a Canvas2D cover and optional Three volume, with configurable material, branding, spine label and pose; its contract, differences from the reference and example are in [reusable objects](reusable-objects.md). Static mode requires neither network access nor installation. Contract, geometry and material regressions: `node --test <skill-dir>/tests/book-*.test.cjs`. Use `BOOK_THREE_MODULE=/absolute/path/three.module.js` to include real meshes; without it, dependent tests record skips, not passes. The [approved case](book-polish-case-study.md) contains hashes, the audit synthesis and the location and limits of external history.
- [AppearanceEditor](../assets/appearance-editor.js) and [scoped CSS](../assets/appearance-editor.css) implement the compact lighting UI, isolated drafts, keyboard/Pointer Events, and storage adapters. [Integration and state contract](reusable-components.md#appearanceeditor-integration); regressions: `node --test <skill-dir>/tests/appearance-editor.test.cjs`. The component does not supply the destination's backend or certify every frozen visual measurement.
- [NeuronPassport](../assets/neuron-passport.js) and its adjacent `neuron-passport/` resources preserve the approved Neuron engine in an isolated same-origin frame. See [integration and source limits](reusable-components.md#neuronpassport-integration).
- Legacy [PassportObject](../assets/passport-object.js) and [scoped CSS](../assets/passport-object.css) provide hinged covers, a turning leaf, fit/material controls and a truthful static fallback. Supply the original BookObject painter and an existing Three loader as documented in [integration](reusable-components.md#passportobject-integration). Geometry/lifecycle regressions use `tests/passport-object.test.cjs`; real meshes require the installed Three dependency or `BOOK_THREE_MODULE`. They do not prove parity with the approved CSS passport.
- [Component lab](../assets/components-lab.html), [controller](../assets/components-lab.js) and [styles](../assets/components-lab.css) connect both modules to sample content, local storage and real rendering diagnostics. [Setup](reusable-components.md#run-the-lab) uses the repository's pinned Three module; installed consumers replace that loader. Controller tests in `tests/components-lab.test.cjs` cover state synchronization and BFCache handling without claiming browser-runtime evidence.
- `assets/library-colors.js` resolves automatic colors by ID and material variations without the DOM or dependencies; it is not the reference's list-based color allocator. The contract is in [reusable objects](reusable-objects.md#portable-automatic-color); regressions: `node --test <skill-dir>/tests/library-colors.test.cjs`.

## Reference experiences

- [Protocol](experience-library.md): turn research into decisions, mechanisms and test criteria, with authorship boundaries.
- [Bounded studies](site-experiences.md): dated source observations and their conditions, including a claim-level collection of six sources and ten observed claims. These are neither components nor an audit of all 202 sites and 2,079 portfolios.
- [Observed lookup](reference-library.md#search-observed-experiences): `node <skill-dir>/scripts/references.mjs --observed --query "sticky navigation" --json` returns the specific supporting claim. Use `--observed --list --json` for valid feature/use-case values; no network observation occurs during lookup.
- [Release validation](release-validation.md) and [evaluation cases](../evals/release-validation.md): input/output freezing, independent trials, separate browser engines/input modes, live reduced motion, honest WebGL/performance evidence and positive/negative retrieval checks. The scenarios are criteria, not claims of executed passes.
