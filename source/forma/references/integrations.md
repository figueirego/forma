# Tool capabilities for Forma workflows

Forma owns design coordination, investigation, implementation decisions and acceptance. The internal specialists provide the methods; this page describes execution capabilities they may need. It does not route work to other skills or install providers. A host may expose a capability through files, a CLI, a browser, a connector or an editor API. Discover the actual interface before using it.

## Choose by the unresolved question

| Need | Responsible Forma module | Capability and required evidence |
|---|---|---|
| Resolve a material design choice | Product | Available native question control or numbered text; actual reply mapped to the shared brief, with recommendation separate from selection |
| Tokens, colors, typography, layout or consistency | Foundations | Source and computed-style inspection; roles, consumers and rendered comparison |
| Controls, settings, profiles or task flows | Interface / Product | Source, UI and event inspection; input, state, effect and persistence |
| Motion, interruption or gesture continuity | Motion | Browser/native input and frame capture; before, during and after the interaction |
| Geometry, materials, lighting or articulation | Objects 3D | Source, renderer or scene inspection; active backend and controlled views |
| Unknown reference or package mechanism | Reference | Source reader or artifact inspector; identity, scope and evidence limits |
| Graph relationships and analytical displays | Graphs & Data | Data and renderer inspection; provenance, totals, picking and equivalent access |
| Target-specific behavior | Platforms | Available browser/device runtime; OS, engine and actual input type |
| Graphic assets and typography exploration | Brand | Existing assets, font inspection or authorized generation; rights and intended role |
| Editable source, tokens or export | Handoff | Design canvas and exporter; stable IDs, bindings, rendered output and format losses |
| Task, accessibility or fidelity checks | Validation | Existing tests and available UI tools; criteria, revision and result per state |

Use the relationship: evidence gap -> Forma owner -> available capability -> observed result -> destination decision. Start with direct source inspection when it answers the question. Another tool or visual reference does not replace tracing the mechanism of a technical defect.

## Execution contract

1. State the question and what finding would change the decision.
2. Inspect the available interface and its current operating requirements. Availability, authentication and permission to mutate are separate facts.
3. Preserve the target, revision and approved context. Prefer existing project tools and assets.
4. Execute only within the user's scope. Do not install services, subscribe, upload private files or start paid generation as a routing side effect.
5. Inspect the result in the destination. Reading instructions does not prove invocation, a saved file does not prove rendering, and a render does not prove persistence.

## Questions across assistants

The [progressive brief](progressive-brief.md) is a host-independent instruction protocol executed by the assistant, not a background service or a universal tool API. Activate Forma using the installed distribution's instructions. Inspect the capabilities and restrictions of the current host and mode before presenting a native question. Never assume another assistant's API exists or enable a mode, plugin or global setting just to obtain a widget.

Use one question with two or three meaningful choices, a recommendation and free text when supported. If the host has no native control, use the same question and numbered choices in text and accept a free-form reply. Keep a single pending question. With asynchronous controls, continue only independent work while waiting; do not queue another design question or execute work depending on its answer. Without asynchronous controls, yield for the reply.

Record actual replies in the project brief, not private assistant memory. A default selection, dismissal, skipped question or elapsed time is not an answer. A correction updates the affected decision and its dependents; switching assistants must not restart resolved choices. Document native-host trials, headless-host trials and simulations separately. Equivalent packaging alone does not prove conversational behavior.

## Design canvas and code

Inspect existing context, rendered appearance, components and token bindings first. Keep actual document, node and instance IDs. Reuse mapped components; returned code is a reference until adapted, integrated and verified. Never substitute a screenshot for an implemented interface.

Declare authority by scope and revision. Check aliases, resolved modes, variants and consumer bindings; matching colors do not prove a token connection. Preserve valid overrides. Apply layout relationships through the editor's actual constraint system. Recover partial attempts without duplicating nodes or libraries; do not publish without authorization.

## Generation and export

Choose one primary production path per artifact. Preserve project, request and execution IDs; polling is not a new generation. An authentication or credit failure does not authorize switching providers. Check which layers remain editable and inspect the final exported file. Return only result links actually supplied or created. Do not send a complete repository as context by default.

## Missing capabilities

State the exact missing capability and affected criterion. Continue source reading, specification, local implementation or available-evidence analysis that is independent of it. Do not call a fallback an executed integration or substitute a different mechanism for an approved reproduction. A missing canvas must not block a local spacing correction.

For optional runtime integration, follow [coordinated production](agent-production.md). For evidence from packages and runtimes, use [artifact investigation](artifact-investigation.md). For refinement and synthesis, use [routing](routing.md) and [approved product evolution](approved-product-evolution.md).
