# Integral Soft Glass reference kit

Use this route for the complete approved landing with the same fonts, artwork,
textures and motion. The authored `assets/soft-glass/landing.html` is an
adaptation and MUST NOT silently replace the approved source in that task.

## Locate the actual artifact

The integral reproduction is a separate local kit, ID `soft-glass-approved`.
Check the user's supplied project/archive first, then this conventional location:

```text
~/.local/share/forma/reference-kits/soft-glass-approved/manifest.json
```

Expand `~` to the current user's home. Read the manifest and verify its SHA-256
file records before reuse. `forma-soft-glass-integral.zip` transports the same
kit to another machine; extract it and use its root as the reference location.
Inspect an unknown archive before serving or executing it.

The kit retains the approved study's branding, copy, fonts and media. It is a
local reference, not embedded in the public Forma distribution or relabeled
as Forma-authored assets. A fresh plugin installation does not prove the kit is
present. If absent, request its path/archive before promising an integral copy.
Use the portable authored adaptation only as an explicit alternative.

## Reuse without losing fidelity

1. Copy the whole kit into a new destination; preserve the reference copy.
2. Serve it over HTTP. `index.html` is the landing, `app.html` the static
   workspace and `designs.html` its visual state viewer. Keep asset paths valid.
3. Preserve actual HTML, CSS, JavaScript and local dependencies before adapting.
   Retain all font subsets and theme/media variants, not only first-viewport
   network requests. Do not substitute screenshots, font fallbacks, generic
   gradients or invented illustrations for the approved implementation.
4. Compare equal CSS viewport, DPR, browser, theme, fonts, scroll and animation
   checkpoint. Decode lazy media before checking below-fold sections. Record
   timer/video differences instead of hiding them with a broad pixel tolerance.
5. Then adapt only the authorized brand/content/stack, recording changed files
   and visual consequences. Text changes affect wrapping; new art affects fidelity.

Global selectors and the script expect their original document structure.
For an existing app, isolate this page or embed it in an iframe first. Do not
paste global CSS into the host and claim scoping is complete. A framework
conversion is a separate adaptation requiring another visual comparison.

## Design-only boundary

Preserve theme previews, tabs, FAQ, sticky navigation, hover/press feedback,
timed demonstrations and local media as presentation mechanisms. There is no
connected login, generation, account, payment, publication or lead service.
The contact form reveals an explicitly labeled visual-demo message; it does
not send or store data. Verify this boundary rather than describing it as real
submission. Review retained outbound navigation before public product use.

## Acceptance and evidence

- File hashes match the approved source before customization.
- Local fonts, both theme variants, textures, mascot and video load without
  requesting assets from the original product.
- Desktop, tablet and mobile preserve section order, wrapping, insets, radii,
  panel proportions and source breakpoints.
- Compare initial/floating navigation, four story steps, both mode panels,
  audience tabs, features, FAQ, contact and footer.
- Check dynamic scenes at known checkpoints. Report uncontrolled media frames
  separately. Reduced-motion captures do not establish normal-motion parity.
- Check missing assets, overflow, JavaScript errors and product requests.

Use the kit's adjacent audit for observed states and limits. Matching files
prove faithful transfer of that source, not every version of an external site,
every GPU or physical mobile device.
