# Optional integrations and honest operation

This skill synthesizes criteria and can work locally. It is not a wrapper that executes every plugin for every task. Discover available tools by name/description; read the current operational skill before using each service. Do not assume installation, authentication, and available tools are the same thing.

## Choose support during refinement

Use the relationship **evidence gap -> selected support -> expected outcome -> application to the target**. The table above offers options, not mandatory dependencies. For example: abrupt gesture -> motion skill to investigate continuity/interruption -> local change -> confirm the rendered interaction. For an inconsistency with an unknown cause, ECC Design System or Impeccable can guide the audit; if local code already explains incorrect padding, fix it directly.

Before invoking support, formulate the concrete question and which result would change your decision. Check installation/connection and read the current operational skill. If a capability is missing, use a compatible alternative and declare the limit; do not install, subscribe, or send private material to another service merely to complete the list.

The coordinator selects the internal specialist according to [routing](routing.md); the support options on this page do not replace that selection. When the user requests ECC, actually use the relevant ECC skill resolved from the current catalog/installation. ECC organizes skills and recipes by case; this does not mean executing the whole collection, nor does it provide proven autodiscovery of this skill's nested modules. When another support tool is explicitly requested, include it in the plan and read its current contract; do not ignore the instruction to minimize context.

Seek new references when an interaction pattern, direction, or technical explanation is missing. Limit investigation to the relevant case and compare role, platform, and evidence. An additional visual reference does not replace tracing the mechanism of a technical defect. Preserve approved identity; another reference's constants do not become project tokens by default.

When independent review could reveal a blind spot, delegate a bounded question with source, state, and criterion. Separate auditing from editing; assign files for parallel implementation. Consolidate into the same diagnosis, resolving disagreements through evidence. In the existing record, gap, support used, result, decision, and verification are enough; small adjustments do not require a new report.

## Figma

For design-to-code, load the corresponding skill before get_design_context, include its required parameters, and obtain a screenshot. Inspect the library/Code Connect and reuse mapped components. Returned code is a reference to adapt, not a guaranteed working implementation. Never use a complete screenshot as an interface substitute.

For canvas editing, inspect existing conventions and nodes first. Use auto layout, variables, and components where appropriate. Preserve returned IDs, handle partial attempts without duplication, and compare the rendered composition. Do not invent file links or publish a library without authorization.

For tokens/components, load the operational library skill in addition to the editing API when required. Declare scope (foundation, component, library, or reconciliation), reuse compatible assets, and verify aliases, bindings, properties/variants, and resolved modes; identical appearance does not confirm token connection. Do not turn a component request into an entire library. Check the current serialization and recovery contract before concurrent mutations or retries.

## Open Design and Superdesign

This synthesis does not install applications, configure MCP, connect accounts, or start paid generation. When a future task requires those actions, consult the plugin contract and session authorization. Do not run the macOS system utility named od as though it were Open Design.

Preserve a generation's execution mode and IDs; polling is not a new generation. An authentication/credit failure does not authorize changing providers. When using a canvas, return only URLs actually supplied by the service. Do not upload an entire repository or private assets as context by default.

## Fallback

Choose one primary route per artifact: existing Figma -> context/components/implementation; existing repository -> local editing with the current system; graphic asset -> an appropriate canvas; binary investigation -> REA. Open Design and Superdesign are production alternatives, not mandatory consecutive stages. Record responsible tool, actual project/draft/node IDs, artifacts, and exit condition. Change routes for a concrete blocker or user preference while preserving decisions and assets; do not generate the same paid work in two services by default.

If a tool is missing, state which part depends on it. Continue the brief, specification, local code, or available-evidence audit that does not depend on the tool. Do not call this plugin execution. Optional dependencies must not block a simple spacing adjustment.

To choose among repertoires/skills, consult [source use cases](source-use-cases.md). Reviewing an integration's documentation does not mean an artifact was created there. If the task is to synthesize principles, do not initiate generation, authentication, or installation merely to mark the plugin as used.
